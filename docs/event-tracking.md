# Event tracking

Open **Events** within a game. The tracker reads the existing game catalog, including parser-produced records in the database's `events` array.

The global **Events Calendar** at `/events` combines enabled games and supports game, category, status, and date-range filters. Calendar settings are remembered in localStorage per account, with separate preferences for the global calendar and each game's events page (`gg-event-view-v1:<account-id>:<game-id-or-global>`). These include list/calendar view, selected game and categories, event type, status, date range, search, completion visibility, balance mode, expanded filters and scheduling settings, summary selection, list-group collapse state, displayed month, and backlog sort order. Existing saved category preferences are retained as a fallback. Dialogs and unsaved date drafts are not reopened after refresh.

## Balance events

Enable **Balance events** to suggest one completion day for each remaining event instead of repeating it on every available calendar day. The planner uses the selected date range, or the next 30 local calendar days for **All dates**. Past days are excluded.

Each event counts as one task. Earliest-deadline scheduling finds the smallest feasible maximum number of tasks per day within that window, then moves flexible tasks away from crowded days without increasing that maximum. Set **Maximum tasks/day** to impose a limit, or leave it empty for automatic capacity. The planner targets seven days before the deadline when feasible without raising capacity, and falls back to the actual deadline when needed. It respects start dates and deadlines, including the full final day for date-only deadlines. It does not estimate play time or infer additional repeat cycles.

Daily counts show remaining planned tasks. Completing an event preserves the other suggested days. Use **Rebalance** to rebuild the plan around the remaining tasks. Changing filters, event dates, the account, or the current day also rebuilds it. Month navigation alone does not move assignments.

Events with expired or missing deadlines, invalid dates, or no available day in the window remain accessible in **Backlog**, with an explanation. Sort the drawer by deadline, game, or completion. It also provides access to completed unscheduled events when **Show completed** is enabled.

Use a date's button to open day details. Both day details and Backlog allow a manual date to be pinned or removed. Pins must respect availability, deadlines, the planning window, and the configured capacity. An undated event can be explicitly pinned without changing its source dates. Automatic rebalancing preserves pins and surfaces conflicts if a later limit or event-date change makes them incompatible.

Pins, daily capacity, and compact density are stored per account in this browser under `gg-event-schedule-v1:<account-id>` (or `guest`), separately from completion and calculated assignments. Balance mode is restored after refresh, and calculated suggestions are rebuilt from current events, progress, filters, and saved pins. Completed events are omitted when generating a new plan. Unchecking an event restores its incomplete status; use Rebalance to assign it if it has no existing suggested day. Objective-level scheduling remains a future enhancement.

## Views and tracking

- **List** groups filtered events into **Active & Upcoming** (initially expanded), **Completed**, and **Ended / Archived** (initially collapsed). Completion takes precedence over availability. Active events sort by deadline, followed by upcoming events by start date and unknown-date events. Ended entries sort by most recently ended first. Completed entries use existing event dates as a fallback because progress has no completion timestamp. Empty groups are omitted. Group titles show filtered counts.
- Rows are shared across the list, backlog, and day details. They show completion, game accents, title, availability, and required-objective progress. Partial progress uses a mixed checkbox and a textual Partial label. Completed titles remain muted and struck through. Unknown dates show Unknown availability; redundant Limited-time text is omitted. Editor-only Edit/Delete actions are inside an overflow menu, with Escape and outside-click dismissal.
- **Calendar** shows a Monday-first month grid, month navigation, and a Today button. Multi-day events appear on every available day unless balancing is enabled. Chips use subtle game-color accents, completion checkboxes, deadline warnings, and detail tooltips. Compact density reduces cell spacing. Date buttons open day details; undated entries remain accessible in Backlog.
- Primary controls hold view, search, game, Filters, and Backlog. **Filters** contains ordinary event filters only. The **Tasks per day** summary opens separate scheduling settings for balancing, capacity, calendar density, and saved manual pins. Compact density is offered only in Calendar view.
- Four interactive summary cards show **Scheduled** (events with suggested assignments), **Unscheduled** (visible events without assignments), **Completed**, and **Tasks per day**. Scheduled opens assigned entries in the list, Unscheduled opens Backlog, Completed reveals and expands completed entries, and Tasks per day opens settings. **Show all events** clears a summary selection. Counts respect ordinary filters but do not depend on the summary selection. Scheduled and Unscheduled respect Show completed; Completed reports completed matches even while that group is hidden. Scheduled assignments and remaining incomplete tasks are counted separately. Availability dates alone do not count as suggested assignments.
- Backlog uses the same filters and can include dated entries without suggested assignments, including historical and completed entries. Default sorting prioritizes active deadlines, upcoming starts, unknown dates, then ended entries. Scheduling errors come from the existing scheduler; when balancing is off, guidance explains how to assign a day.
- Type filters, search, and **Show completed** apply to both views.
- Select an event's title to open its linked Story Guide page when one exists, otherwise its attached HTTP(S) URL. Completion controls are separate and do not navigate. Events without a valid URL remain visible.
- Completion uses existing per-account player progress, or `gg-player-v1` browser storage for guests. Linked guide placements share the event's canonical progress. Event completion toggles all required objectives, with confirmation for multi-objective actions, and leaves optional objectives untouched. Failed saves restore the prior state and display an error. It does not change a database event's shared completion flag.

Parser records retain their original shape. The API exposes their title, URL, icon, type, and dates through the shared catalog adapter, without copying them into editable event records when another catalog item is saved. Parser event IDs are deterministic and include the event period, keeping completion stable across reloads and fresh for a newly parsed period. The UI does not invent recurrence schedules or reset dates independently of the parser.

Date-only start and end values use local calendar days. End dates include the full final day; timestamp values retain their explicit time zone. Countdown labels refresh every minute. Editors can add custom events with a type, dates, and URL; existing custom records retain edit/delete controls in the list view. Parser event definitions remain managed by the parser.
